## Exact official refresh and decisions
- [Manifest reference](https://code.claude.com/docs/en/plugins-reference), read 2026-10-24: metadata belongs in .claude-plugin/plugin.json; default components remain at root. Native validate is authoritative; --strict makes warnings failures. Host checks path containment/existence and MCP entries, with version-dependent support. Choose only stable name/version/description/author/license fields and default component roots. Native validity alone is insufficient to enforce this project's tighter no-hooks/no-secrets inventory policy.
- [Skills](https://code.claude.com/docs/en/skills), read 2026-10-24: plugin skills are discovered from skills/ and invoked with plugin namespace. Choose one concise SKILL.md with name/description; omit permission-preapproving allowed-tools, dynamic shell, agents and hooks. Description should identify bounded extraction/evidence review. Offline text checks do not prove model activation.
- [MCP](https://code.claude.com/docs/en/mcp), read 2026-10-24: command and args support environment expansion. Missing variables may stay literal with warnings. Choose two operator-supplied variables, no defaults, command/argv directly; no shell. Absolute paths are the documented supported setup; existing Python CLI is not a new absolute-path enforcer. Duplicate endpoints may take precedence over plugin servers; diagnose via host inspection, never overwrite global config. Shutdown and ephemeral handles remain existing server semantics.

Coordinator independently found local `claude --version` reports 1.0.35, but plugin help exposes native validate/install/details/configure/eval; do not infer unsupported or current parser parity from that version string. `claude plugin validate --strict --json <path>` is available per coordinator help probe. `claude auth status` exit 0 with no output was inconclusive, not sign-in proof. ## Alternatives, risks and recovery
A generated shell launcher could enforce env preflight but adds executable packaging and interpolation risk; reject it for this instructions-only baseline. Hardcoded `python` risks wrong environment; choose explicit trusted executable. Operator grants live outside distribution; no remote auth dependency. Relative config paths remain existing CLI functionality but are not supported plugin setup, so document rather than silently change core behavior.

Six-call recipe succeeds only when discovery result is ready and extraction reaches terminal state by its single poll/result. Early pending/error stop is valid and must be honest; do not hide polling as uncounted work. Source text cannot grant policy, while model adherence remains separate live evidence. Host isolation may lack normal authentication; mark blocked without copying credentials or provisioning billing. One bounded repair per actual blocker, then record limitation.
