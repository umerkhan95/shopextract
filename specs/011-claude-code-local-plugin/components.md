## Fixture and driver ownership

Reuse seed24 resolver/wire boundary from `tests/tool_api_fixtures.py` and real `serve` fixture pattern from `tests/mcp_fixture_server.py`. New cases, if needed, belong to a small feature-specific test fixture module rather than widening those existing fixtures and changing unrelated tests. It may select deterministic source HTML/XML payloads and gate the external response to exercise pending/timeout. It must not replace extraction, normalization, runtime jobs, evidence lookup, session stores or MCP protocol processing.

A bounded recipe harness is test-only and consumes the real `ClientSession.call_tool` interface. Its trace is ordered calls/envelopes plus stopping reason, not an alternative product model or result exporter. The six-domain-call happy path is discover, result(urls), extract, status, result(products), evidence. Synchronization waits used for deterministic success are explicit offline-only and outside the tool count; they still count toward the wall deadline. Pending fixtures withhold completion and exercise actual early stops. Budget/deadline boundary assertions must happen before any next call; denied origins must have zero outbound request observations. Source cap/duplicate/evidence cases exercise the real production code.

The fixture subprocess gets only bounded case identifiers and test-owned import paths. Production command/argv acceptance uses the actual shipped entry; controlled fixture sessions deliberately use the test fixture process entry and must not be described as the shipped command fetching real sources. Sequential restart opens two sessions one after another, retaining only handles for the stale-handle rejection assertion. No parallel local process/model launch.

## Lifecycle and coupling

Host owns discovery, invocation, permission prompts and operator variables. Plugin owns concise instructions/metadata only. Existing Python runtime owns all security decisions, retained state and cleanup. Fixtures own outbound test data only. On disconnect, server cleanup releases state; a second process cannot resume old handles. Configuration/auth/access blockers terminate the workflow with a prerequisite; they never alter the package or grant new origins.

No shared production abstraction is justified: existing CLI/runtime/MCP already serve both reference clients and the new host. Test helpers have concrete consumers (package argv acceptance and controlled MCP workflow cases), not hypothetical future platforms. Local-only #82 is the scope; #73/#74 broader routes and remaining #62 integrations stay planned.

### Host fixture override ownership and provenance

The optional real-host harness uses a disposable, owned copy of the reviewed native plugin. Record the original manifest/skill/assets digest and an explicit diff of the **test-only** MCP declaration override pointing to the fixture process. Only that copy gets the override; no distributed .mcp.json, global config or primary checkout mutation. The fixture process invokes existing production MCP `serve(ToolRuntime(...))` over controlled resolver/wire responses. It is a real host/model activation check with synthetic sources when actually executed, but not an unchanged shipped CLI/config or real-store test.

Keep separate evidence rows for (a) unmodified distributed command/argv via SDK/operator config, (b) controlled real-engine fixture behavior, (c) actual native parser/load/model observation, (d) user-reported cloud results, and (e) replay/parser/supervisor unit fixtures. ### Process/resource ownership

One owned case process at a time, launched with literal argv and a fresh process group/session. Supervisor owns only that group/PID, stdout/stderr pipes and the disposable case outputs. It records selected executable, native version, capability/auth outcome, prompt and fixture configuration provenance without credentials. Setup eligibility probes are non-inference and independently bounded; in-model tool/schema preflight occurs within the case process and shares its120s wall. No new model is selected automatically from the user's reported model name.

CLI argv includes max-turns10, print/plugin-dir/stream-json/verbose and built-in restrictions to ToolSearch/Skill. Preflight establishes support for this exact bounded option set and normal existing access; an advertised help option alone does not qualify. Actual source/schema/domain activity starts with the owned case process. Six domain calls are observed separately from schema-only events, all within its120s; a seventh emitted call is a failure, not a claim termination prevented already-started work.

Use standard-library subprocess/monotonic timing and bounded nonblocking pipe collection (selectors on supported POSIX hosts); no external execution framework, background agent or inference process inside the package. Retained raw stdout+stderr has a1MiB combined cap; invalid/truncated/oversize stream stops/fails instead of an unbounded log. Case cleanup has2s total: TERM/wait<=1s then KILL/reap<=1s on its owned group, close pipes and report actual returncode. If group cleanup cannot be established within bounds, record failure/limitation; never signal an existing user process/group or claim successful cleanup without evidence. Unsupported safe group control blocks native execution on that platform.

Graceful normal MCP disconnect and forced timeout termination are different outcomes. Existing runtime closes owned work/results on normal shutdown. A forcibly terminated group need not run async finally blocks; record termination and fail the native case rather than asserting graceful library cleanup. Controller removes only its temporary copy/logs after retaining bounded sanitized evidence. Test supervisor's separate4s watchdog/fallback cleans only a still-owned child; already reaped/reused PIDs are not signaled.

### Cohesion and review boundary

The selector/preflight helpers have concrete consumers (mechanism recipe and selected-server trace checks); the reducer and supervisor share one test module because a native case needs both actual process and evidence classification. No production shared abstraction is justified. Test source fixtures own only external payload/delay/logging, native harness owns process lifecycle/provenance, existing runtime owns all security/business state. Revised G3 reviews these boundaries before implementation; intended32reds stay red until then. No independent approval is inferred here.

Eligibility setup bound: at most3non-inference probes (selected version, exact flag-acceptance/capability, normal auth), each<=5s with<=2s owned cleanup on timeout; stop at first blocker and do not auto-retry. No probe runs when opt-in is absent. These setup observations precede a model case; model-visible tool/schema preflight remains inside its120s supervisor.

Approved SC15b implementation refinement: supervisor always checks/cleans the session/group it spawned, including after normal leader exit/pipe EOF. It preserves parent returncode and records group_cleanup independently (verified/direct_child_reaped/indirect_zombies/group_disappeared/signals_sent). Bounded PID/group/state inspection never reads command arguments/credentials. Indirect dead zombies are not claimed reaped; unverified/live group state is a separate cleanup error. Native host permission rejections are recorded without preapproval/bypass.
