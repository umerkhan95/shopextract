## State and compatibility contracts
Each invocation progresses preflight -> submitted -> pending/terminal -> evidence/report or explicit early stop. Six-call success path: discover, job_result(urls), extract, job_status, job_result(products), evidence. `job_result` may be unfinished: stop early rather than add polling. The status call is a bounded poll, not a completion guarantee. Use one chosen candidate URL, extract max_items=2, report at most two returned records and one retained evidence record. Calls after a budget/deadline stop are forbidden. Protocol metadata discovery is not an extraction call, but any host tool execution used for preflight counts toward the same six-call budget. Resource reads also fit the wall deadline; no hidden tool execution. Fixtures may await real completion without calling an extra tool to obtain deterministic mechanism evidence; this does not prove model behavior.

Source fixture seed 24 is deterministic, no random sweep. Extend only the controlled outbound boundary; never fake runtime extraction/jobs/evidence. Distinct cases cover syntax, launch boundary, source policy, normalization/support fidelity, asynchronous early stop, lifecycle and model activation. Existing server limits remain authoritative. A safety inventory check must not be described as the native host rejecting files it accepts.

## Bounded live plan
After offline success, inspect CLI help/auth without exposing credential files. Use existing normal sign-in only, a disposable `CLAUDE_CONFIG_DIR` and project directory; do not copy secrets or change global config. If isolation prevents normal authentication, record blocked; do not initiate new billing or credential provisioning. First save install/discovery smoke, then expand only if possible.

Targets: operator-owned controlled authorized source origin, exact endpoint recorded before run (none preapproved yet). Three prompts maximum: (1) explicit `/shopextract:shopextract-review` discover/extract/evidence for authorized fixture, (2) unrelated short arithmetic prompt, (3) missing-grant prerequisite prompt. Each case <=6 tools, <=2 products, <=120s; one fresh install/load and at most one update, no retries. Use host trace to count actual calls; stop on deadline/permission uncertainty/budget breach. No bypassPermissions, public publication or broad model run. Save sanitized command, version, install/update/disable state and summaries under evidence/. Required host activation is blocked when normal client/access is unavailable; offline mechanism results stay separate.

Native integration opt-in: default pytest skips the native proprietary Claude parser check; this is not a parser pass or compatibility result. Run `SHOPEXTRACT_NATIVE_CLAUDE=1` explicitly for native evidence; absent client then fails as blocked, with actual CLI result recorded separately. SDK/package checks remain normal offline tests.

Implementation-stage supplemental assertions (same FR04/SC03/SC06): evidence lookup must leave observed outbound request count unchanged; a fresh real extraction after sequential process restart keeps the canonical product ID and mints a distinct owner handle. This tests source-support isolation and canonical stability separately from handle expiry. Total products across those two SDK sessions are two. Project-only package policy additionally includes the standalone MIT LICENSE notice; it does not infer native host acceptance.
