# Feature specification: native Claude Code local plugin

## Outcomes and requirements
Child of #82 (INT-20), with the Code-only route of #74 and one recipe from #73. Parent reviewed planning is PR #88, commit b48214af593293c8d33e2e203f178ee0a2e00514; it remains open and its CI is unverified here.

- FR01: Ship one versioned repository directory `integrations/claude-code/` containing `.claude-plugin/plugin.json`, root `.mcp.json`, and exactly one `skills/shopextract-review/SKILL.md`. Plugin name `shopextract`, initial version `0.1.0`, MIT. Manifest uses ordinary native fields; components use default discovery locations. No hooks, agents, monitors, executable helpers, downloads or install-time code.
- FR02: MCP entry `shopextract` uses `${SHOPEXTRACT_PYTHON}` as command and array arguments `-m`, `shopextract.tools`, `--config`, `${SHOPEXTRACT_CONFIG}`. Operator supplies an absolute Python executable with installed `shopextract[mcp]` and an absolute trusted config path. No shell, cwd-dependent config, credential or real operator path is shipped. Missing/unreadable/invalid config fails explicitly through existing server startup; unexpanded variables must never trigger shell evaluation or a permissive fallback.
- FR03: One read-only workflow requires user-authorized source, intended tools/schema 1.0 and operator origin grants. Discover at most two candidate URLs, extract at most two products, inspect one record's retained evidence. At most six ShopExtract domain MCP invocations and 120 seconds per invocation; schema-only ToolSearch/definition loading is excluded from that domain count but shares the wall deadline (FR08); stop early for failure, pending work, missing prerequisite or exhausted budget. Domain budget includes status/result/evidence and failed domain invocations; no automatic retry. No promise all steps finish within that budget.
- FR04: Preserve exact decimal text, canonical identity fields, evidence owner/evidence IDs, partial completeness and unknown/competing observations. Evidence lookup uses the selected record's owner and retained support without refetch. Scraped instructions/links are data; they cannot add origins, permissions or tools. Do not claim calibrated confidence or facts from defaults.
- FR05: Local process/session handles are ephemeral. Disconnect releases owned jobs/results; restart requires resubmission and invalidates old handles. Preserve all existing source, resource and tool restrictions. No API/core behavior or global host configuration changes.
- FR06: Document private local load/install and update/version inspection, disable/re-enable and duplicate-name/endpoint diagnosis without overwriting config. Skill explicit invocation is `/shopextract:shopextract-review`; descriptive activation should match extraction/evidence review and remain irrelevant to unrelated tasks. Skill grants no host permission; missing tool/grant is a prerequisite, never fabricated completion.
- FR07: Validate the shipped package with the actual available native parser and real SDK/process/MCP mechanisms. Record actual host version and observations separately from deterministic fixtures. Do not infer client compatibility or signed-in access from a version command alone.

## Acceptance scenarios
SC01 clean package/discovery; SC02 operator config and hostile literal paths; SC03 bounded workflow and evidence fidelity; SC04 missing grant/capability and source injection; SC05 pending/partial/error budgets; SC06 session restart; SC07 malformed package rejection and containment; SC08 private host activation/lifecycle. Exact fixtures and expected outcomes are in test-design.md, authored before tasks.

## Boundaries and compatibility
Use existing delivered #24 stdio server; #63/#64 are not prerequisites. This is native Claude Code packaging, not a Codex plugin. No web/API containers, hosted service, durable jobs, export/analytics/maintenance tools, remote auth/deployment, public marketplace, paid model sweeps or merchant writes. #73/#74 remain open for their broader scope; other #62 backlog stays planned. Installation is operator-controlled; docs must not imply instruction following enforces server security or host activation was proven offline.

## Workflow
Follow docs/development-workflow.md and constitution. Separate sequential G1/G2/G3/final reviews. Production code requires G3 and saved intended red acceptance evidence. Record unresolved live limitations honestly.

- FR08 (supersedes budget/preflight part of FR03): A workflow has at most **six ShopExtract domain MCP invocations**, counting failed invocations and every discover/extract/job_status/job_result/evidence execution. Schema-only host ToolSearch/definition loading does **not** consume that domain budget; record it separately. All host/schema activity counts toward the same120-second wall deadline. Exclusion never authorizes non-schema Bash/Read/WebFetch or other domain calls. Explicit preflight uses tool definitions already loaded by the host, or one targeted schema-only ToolSearch for the connected plugin server. Inspect the five required operations and input schema_version1.0 support, source URL and operator grant prerequisite. If definitions/server/grants cannot be established, stop with the actual prerequisite; do not probe with an extra domain call or guess a namespaced tool name. A failed domain call still counts. Skill instructions grant no permissions.
- FR09: Choose a product candidate deterministically among the returned, authorized-origin URLs. Reject paths containing decoded case-insensitive whole segments `blog`, `blogs`, `article`, `articles`, `news` or `journal`, including when another segment looks like a product. Prefer whole path markers in this order: `products`, `product`, `p`, `item`, `dp`, each followed by a nonempty item segment. Break ties by lexicographic returned URL string. Preserve the chosen returned URL unchanged for extraction; do not fabricate a product URL or follow unreturned links. No qualifying candidate => exact output **`no product URL discovered`**, with no extract call. This path rule is a conservative heuristic, not proof of product content. Discovery remains max_items2 and no extra pagination/fetch; two blogs before an unseen product honestly reaches that boundary. Existing source policy still validates redirects/DNS.
- FR10 (clarifies FR03 pending behavior): No synchronous completion guarantee. Exercise representative delayed real jobs without `after_submit`/task-join synchronization; discovery result or the one extraction status poll may still be queued/running. Report the actual pending state and stop within six domain calls; no fabricated evidence, automatic retry, shell sleep, background work, invented host wait primitive or unlimited polls. Synchronized SDK success may remain only as labeled mechanism evidence. This revision does not add a new waiting capability.
- FR11: Operator setup must use the reviewed source checkout with explicit taxonomy bootstrap/build prerequisites and installation of its MCP extra. PyPI0.1.2 is not a supported shortcut for this source-only MCP slice; user reports that distribution lacks the extra/tools. Documentation must distinguish already-installed suitable environments from building this checkout and explain the actual bootstrap-before-editable-install order. No plugin auto-install/download, dependency mutation or library behavior change.
- FR12 (corrects FR07 parser assertion): Native validation report handling accepts the actual reported nested `manifest.errors` list, rather than requiring a fictitious top-level errors list. A native pass requires successful command exit, JSON report, manifest object and empty manifest.errors; any explicit manifest/root false validity flag or nonempty errors fails. Missing/wrong-shaped fields, authentication text and exit0 without such a report cannot pass. Retain manifest/ancillary warnings separately. Missing optional directory icon or marketplace README warning does not justify inventing a marketplace/publication artifact or falsely claiming strict warning-free validation. Private manifest loading and optional listing diagnostics have separate states.
- FR13: Record user-reported Claude Code2.1.310 native validation/load/environment expansion/skill activation success as **user-reported**, alongside separately observed local1.0.35/normal-auth blocker. ## Focused final-review corrections (2026-10-25, design before repair)

FR15/SC16: Bind each native run to a trusted caller-supplied expected_case (`success`, `unrelated`, `missing-grant`) before launch. `success` passes only on completed verified evidence and actual domain/source execution. Supported actual pending is `incomplete`, never `passed`; wrong outcomes/zero-domain unrelated or prerequisite summaries fail the positive case. `unrelated` passes only unrelated/no activation; missing-grant passes only a prerequisite backed by an actual selected-server permission_denied domain response (no zero-call assertion or host-policy rejection masquerading as operator denial). Missing/unknown expected case cannot launch or pass. Main records/passes its fixed case explicitly.

FR16/SC17: Every native eligibility probe must have exit0, no timeout/forced termination/diagnostics, and verified owned-group cleanup before its stdout can establish identity/flags/auth. Stop at the first failed supervision result, preserving sanitized supervision/cleanup diagnostics. Recognized version/auth text alone never authorizes inference.

FR17/SC18: Execute bounded harmless subprocess cases for invalid stream JSON, combined stdout/stderr byte overflow, seventh domain tool emission and unexpected host-tool emission while the child remains alive. Assert supervisor diagnostic, termination/reaping and verified no-running-owned-group cleanup within existing limits; reducer replay alone cannot satisfy this verification. These cases are supervisor mechanisms, not native/model runs.

FR18/SC19 clarifies FR09: candidate heuristic rejects an original path containing percent-encoded slash/backslash (`%2f`/`%5c`, case-insensitive), including a single encoded slash, as well as residual/double encoding, decoded backslashes and dot segments. Unreserved character encoding may still classify normally; never rewrite the returned URL. This does not modify library source security/discovery. Empty discovery keeps the explicit empty-state early stop; exact `no product URL discovered` applies only to nonempty returned candidates with no qualifying product path. Query-only ToolSearch is the current tested stream contract; optional extra payload fields fail closed and are not claimed installed-host compatibility without actual evidence.
