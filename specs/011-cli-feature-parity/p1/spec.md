# P1 extraction behavior

2026-10-25; additive extraction slice, parent FR02–04/09/10. P0 completed evidence reused.

## Outcomes and requirements
- F1: Preserve nine legacy commands/defaults. `--output-format json detect|discover|extract` returns the P0 envelope. Add `extract-one URL`, `feed URL`, `normalize FILE`, `quality FILE`; these emit envelopes even under default root format.
- F2: `extract` retains --max/-n=20,--format/-f=json,--output/-o. Add --platform (native enum), --shop-url, --enrich-identifiers, --restore-short-gtin, --storefront FILE, --timeout (0<seconds<=300, default30), --browser/--no-browser, --allow-llm, --llm-model (default openai/gpt-4o-mini), --llm-key-env (default SHOPEXTRACT_LLM_API_KEY), --llm-max-calls (1..10, default1), --llm-max-output-tokens (1..4096, default512), --llm-max-input-bytes (1..32768, default8192), --llm-temperature (0..2, default0.2). New controls opt legacy extraction into the bounded policy; plain legacy stays unchanged. Machine --output with --format csv is rejected before fetch; JSON file uses the same full response envelope as stdout, atomic replacement. Maximum --max 1000 for bounded paths; legacy defaults unchanged.
- F3: `discover` adds --platform/--timeout/--browser, max1..1000 on bounded paths. `detect` adds --timeout only. `extract-one` has timeout/browser/LLM options, returns raw typed value (no invented normalization); `feed` has --shop-url/--timeout/--max (1..1000 default1000), explicit retained count and truncation. `normalize` has --platform (default generic), --shop-url, --restore-short-gtin. `quality` exposes product scores and native batch score.
- F4: Payload extraction `{products:[native portable v1 record],raw_products:[evidence-codec values],platform,tier,quality_score,urls_attempted,urls_succeeded,errors,observation_scope,catalog_complete,incompleteness_reasons,product_count}`. Raw extraction `{product:encoded raw object}`. Discover `{urls,count}`; normalize `{products,product_count,dropped_indices}`; quality `{scores,batch_score,product_count}`. Decimal/datetime use native `$type` tags; nested evidence/variants remain intact. No `default=str`. Native catalog coverage unknown differs from operation completion. Errors or known incomplete extraction emit partial envelope/exit3 with retained data. Unknown coverage alone is not operation failure. Empty extract-one emits E_OPERATION/exit1 with unavailable data (native empty dict is not usable partial work). Explicit source product-budget exhaustion retains records and emits partial/exit3, retryable=false; user-requested caps never trigger wrapper retry.
- F5: FILE is UTF8 JSON path or `-` stdin, <=1MiB; strict duplicate/nonfinite rejection, depth64/100000node bounds; <=1000 records. normalize/quality accept one raw object or list of raw objects; quality additionally accepts extraction/normalization envelope portable records, converting native records to scalar product dicts via native codec. normalize never interprets portable records as raw capture; rejects them. Empty list valid; malformed record array rejected before algorithms. Storefront FILE is closed object of native string keys endpoint/access_token/protocol/token_type/customer_access_token/customer_id; protocol requires explicit magento, auth context requires explicit bigcommerce. No credential values echoed.
- F6: Bounded execution uses context-local policy inherited by nested async work, never environment mutation. Non-LLM policy disables env resolution and nested LLM helper. Browser disabled by default on bounded/new surfaces; explicit browser opt-in requires existing browser executable, missing dependencies E_DEPENDENCY with install guidance, no installs/downloads. Native legacy policy remains absent. Browser launch control enforced at shared browser configuration seam, HTTP parsed products remain usable without browser.
- F7: LLM explicit opt-in supports explicitly selected LiteLLM provider/model identifiers, including an already running Ollama endpoint. Reuses native fallback orchestration but replaces unbounded crawl/chunk/provider strategy while policy active: one sequential bounded HTTP input per permitted URL, max input UTF8 bytes, one completion per URL, max output tokens, num_retries=0, timeout bounded by operation deadline. No key argument or credentials in output. Hard currency billing guarantees are unsupported; caps constrain submitted work, providers may bill timed-out work. The wrapper never launches/downloads local servers/models; local execution requires an already running configured endpoint. All LLM controls without --allow-llm rejected; credentials read only after all validation. Response must be JSON object/list of objects; errors remain sanitized. Browser and provider verification mock external boundaries only.
- F8: Invalid cap/platform/storefront/LLM combination fails before native side effects. Timeout cancels owned coroutine and awaits async cleanup; Ctrl-C produces exit130. HTTP native internal retries are unchanged; operation deadline bounds elapsed work. The LLM boundary explicitly disables provider retries. No cross-process hard memory/runtime guarantees claimed.

## Scenarios
S1 full11 portable records/money/evidence; S2 native controlled Shopify/feed/generic parsing; S3 actual normalize/quality; S4 option forwarding/trust validation before fetch; S5 timeout/cancellation/policy isolation; S6 optional browser/LLM bounds; S7 legacy compatibility; S8 bounded live smoke.

Coverage clarification: any extraction/feed failure or known incomplete state with
zero usable products emits E_OPERATION/1/null/unavailable. A successfully empty
native catalog with no error remains success. Context state serializes overlapping
nested LLM helper submissions via one operation-owned asyncio lock.
