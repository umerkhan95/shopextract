## Mandatory scope and resource route

Complete pinned English Google catalog is the default target of NEW explicit aggregation; every parent and leaf must pass the real mapping/public projection pipeline. Legacy defaults stay unchanged; unclassified products remain valid. Catalog support denominator is G; Shopify crosswalk audit denominator is S, not assumed one-to-one. Source dispositions partition every S ID (mapped-single/mapped-multiple/explicit-upstream-unmapped/missing-rule/invalid-reference/version-unavailable) with row diagnostics separate. Invalid source/target references block crosswalk publication, no silent drop. Targets without inbound rows still remain fully usable.

Preferred packaging is full preprepared catalog/notices where official terms support it; fallback is explicit operator-provided COMPLETE official resource plus same validation/offline checks. Terms gate the affected acquisition/distribution route only; unrelated offline code may proceed. Missing provisioned full resource blocks overall integration completion, not a product's admission once an aggregate snapshot runs. No partial-sample fallback or code-only-ready claim. Pin namespace/header/locale/source and generated digests; exact historical lookup and atomic default-pointer updates preserve old reports.

## Reuse and rejected alternatives

Reuse Shopify resource staging/verification patterns without Shopify attribute assumptions; extract shared helpers only for demonstrated consumers. Reuse native category mapper/binder and relevant-target options: full catalog/index outside requests, native1000targets/rules/100terms/256KiB ceilings stay. No5595-entry job registry or manually authored category profile list. Preserve source observations; official/trusted crosswalk decisions separate. All eligible routes retained; direct/crosswalk conflicts ambiguous absent explicit versioned override. Broader-only/many-target mappings never falsely become exact leaves.

Use additive local companion/snapshot over native portable/evidence, not Product replacement/event platform. Unknown attributes display with labels/values/support without manual semantic classification; approved finite unit/key semantics enable safe alignment, explicit variant/pack/model uncertainty remains a grouping veto. Strong supported identifiers do not override known conflicts. Current/as-of offers use retained inputs and scope, no currency conversion/checkout acquisition. Distinct products get specification view, not exact-offer grouping.
