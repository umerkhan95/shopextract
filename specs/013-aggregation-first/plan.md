## Proposed wire, errors and persistence

Aggregate envelope has its OWN integer `schema_version:1`, immutable `snapshot_id/revision`, `as_of`, catalog/crosswalk/mapping/group/unit policy identities, native `records`, independent `source_categories/classification_projections`, `specifications`, `groups`, `offers`, source diagnostics and completeness. Evidence references include native record owner/snapshot scope. Exact decimals/UTC values use existing portable codec. Google classification carries target namespace/version/locale/digest/ID, source observation references, route/rule versions, precision and mapped/ambiguous/unmapped/unavailable outcome; target identity never fills unknown observed-source version. Category/evidence export companions bind exact payload bytes/order and remain separate projections.

Resource manifest separately identifies schema/header/locale/acquired time/source URL+digest/generated digest/node-root-leaf-edge counts/notices and pinned optional crosswalk pair. Immutable directories keyed by version+locale+digest; validate staged update before changing default pointer. Snapshot files embed policy/resource identities and retain old report revisions; no automatic source refresh or legacy DB migration. Native category original_binding and config_digest remain authoritative; new named projection must not overwrite old Shopify binding.

Proposed typed failures distinguish `resource_missing`, `catalog_invalid`, `resource_ambiguous`, `catalog_version_mismatch`, `mapping_invalid`, `cursor_mismatch`, `limit_exceeded`, `publication_failed`; child G2 maps these to existing E_USAGE/E_OPERATION/E_PARTIAL plus native error details/retryability without inventing a parallel CLI envelope. Unknown ID/path is an explicit lookup miss, not corrupt resource; unknown product mapping retains usable product. Invalid crosswalk publication fails as a whole with quarantined diagnostics; no active half-index. Required supported target failures prevent100% completion even if data remains usable for diagnostics. API/CLI schema resources/capabilities document all new operations and exceptions; no callback/executable config.
