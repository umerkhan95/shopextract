# Proposed interfaces and report shape (no implementation)

`load_live_profile` keeps v1 contract unchanged. v2 uses same top-level keys, schema_version2, every site's source_kind production and no css_schema; limits exactly {invocations,products,seconds,output_bytes} with maxima {2,4,120,1048576}. Existing site identity/scope/mapping/catalog/config validation remains applicable to selected source inputs, but does not imply production redirect/subrequest enforcement.

Internal worker entry module (for example `shopextract.taxonomies.google.live_worker`) accepts bounded JSON input over stdin, emits one bounded result envelope to stdout; diagnostics go stderr. Input keys are url/platform/shop_url/max_products/timeout. Worker validates types, calls actual async `shopextract.extract(... max_urls=1, include_categories=True)` within `execution_policy(ExecutionPolicy(browser=True,llm=None), timeout=remaining)` and a timeout, and serializes raw rows plus tier, errors, urls_attempted/succeeded, completeness metadata. No credentials/profile mapping rules are passed. Redirect logs to stderr so Crawl4AI print output cannot corrupt protocol. Parent validates envelope, schema, array/dict types and limits before trusting output.

Internal reusable `run_owned(command, *, input_bytes, timeout, maximum_bytes, cleanup_seconds)` returns bounded stdout/stderr, returncode, timed_out/output_exceeded, cleanup_complete (and owned process identity only when useful). Implement one sequential child group, start_new_session, monotonic deadline, bounded streaming readers, finally group cleanup/reap and cleanup-status verification. Reserve cleanup within timeout. Do not run a second consumer when cleanup fails; unsupported platform fails before launch. For Linux subreaper, restore prior process state in finally and reap only owned group descendants. Any concurrency limitations must be documented/enforced, not hidden processwide mutation.

`verify_google_live` branches on validated profile version/source_kind. v1 unchanged static path; v2 calls the production worker through supervisor, reuses same supervisor for normalization/export commands, and shares deadline. Test injection if needed must be explicitly controlled and cannot create live_verified true. Prefer tests of worker with controlled HTTP/Crawl4AI external boundaries plus independent real process supervisor tests over public testing hooks.

Production item has extraction={path:production,status,tier,urls_attempted,urls_succeeded,errors,completeness,browser:{enabled:true,attempted:null},llm:{enabled:false,reason:no_configured_budget},attempts:{api:unknown,discovery:unknown,unified:unknown,css:unknown},process:{cleanup_complete,...}}. Policy-denied item reports extraction not_run and zero starts. Keep legacy fetch/parser fields explicitly not_applicable for pipeline results, never fake HTTP200/source byte counts. Overall report usage includes exact pipeline_invocations/products and network_requests:null/network_bytes:null for v2; existing v1 usage untouched. Raw artifact hash records actual bounded worker data; not a source HTML hash.

Error paths: child timeout/output/invalid JSON/nonzero exit → extraction failed/blocked with bounded reason, cleanup verified, mapping not_run. Empty raw → unavailable, no mapping/export. Missing category → needs_review. Truncated rows → incomplete metadata. Policy denial → skipped_network_policy before child. Cleanup failure → fatal report and no further child. Report status success remains conjunction of mapped classifications and actual export readback.


## SliceA interfaces

`extract_with_categories(..., source_mode='native', **extraction_options)` validates source_mode before I/O. Production branch calls existing top-level extract with new opt-in category capture enabled. Additive `extract(..., include_categories=False)` (or a reviewed equivalent explicit internal capture context) feeds existing `_try_api_extraction` include_categories/category_mode and UnifiedCrawlExtractor(include_categories=False) constructor; propagate to both HTTP and browser parser branches and generic CSS schema as needed. Preserve default no-category source shapes. Do not normalize Product objects back into raw input. Both branches then share existing normalize_with_categories loop.

Extraction-backed CLI functions decorate with existing execution_options(), pass options through policy_options, and use one run_operation/execution_policy context around complete multi-URL/watch operation. Remove duplicate timeout decorators and hardcoded policy only from operations that actually extract. Category CLI adds source_mode native|production with default production; library default stays native. Existing secret redaction includes storefront and LLM secrets.

Shared browser configuration adds private environment-proxy decoder returning Crawl4AI ProxyConfig or None. All Standard/Stealth/Undetected BrowserConfig paths receive it; unsupported/malformed configured proxy raises redacted error, never direct fallback. Preserve env values unchanged and do not expose them in report. Tests use synthetic env and installed configuration object, not actual sensitive proxy values.

FP-FR8 amendment: worker input platform accepts auto or Platform value; only auto becomes None in native extract call. Result includes platform=result.platform.value and validator requires actual Platform value. Version2 mapping receives a site copy with returned platform, never modifies profile input. Preflight platformauto uses generic solely for existing target semantics; reject scoped rules before transport.

FP-FR8 invariant: the returned platform must be a real Platform value and must equal an explicitly declared profile platform; only auto permits a detected value to differ. Reject mismatch before normalization/mapping.
