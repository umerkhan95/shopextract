# Bounded source research

Sources inspected locally 2026-10-31: `_extract.py`, `_execution.py`, `_cli_extract.py`, `_discover.py`, `extractors/unified.py`, `extractors/css.py`, `extractors/_browser.py`, `taxonomies/google/live{,_profile}.py`, `_capture.py`, `_cli_data.py`, `tools/execution.py`, `tools/security.py`, `scripts/run_tests.py`, repository instructions/constitution. No new external facts needed.

Findings: top-level extract tries platform API then discovers URLs, probes UnifiedCrawl, uses CSS and finally optional LLM. extract_one omits API/discovery/CSS and is unsuitable as full-chain substitute. UnifiedCrawl itself tries HTTP structured data then browser escalation when policy permits. CSS uses browser extraction. execution_policy disables unintended environment LLM use but does not enforce raw network counts/bytes/origins. max_urls constrains retained/discovered URLs, not discovery HTTP requests. Browser library may issue arbitrary subrequests; final result tier is not an attempt trace. Default production structured parsing has its existing category behavior; verifier must preserve original raw capture and accept unresolved categories rather than reparse into invented evidence.

Decision: explicit version2 production profile with truthful invocation/time/output/product bounds and unknown network counts, while version1 static guarantees remain intact. Reuse top-level extraction and existing mapping/export. Do not add a duplicated fallback engine or global httpx monkeypatch to production. Child execution with inherited environment proxies respects platform policy; do not use tools.security's direct pinned transport as a workaround for environment proxy controls.

Lifecycle reuse: production library has no owned POSIX process-group supervisor. tools.execution.OwnedProcess uses multiprocessing daemon child for synchronous domain work, not browser-grandchild supervision. scripts/run_tests.py has tested POSIX start_new_session, Linux subreaper and process-group cleanup logic; reuse its design in one focused internal library component rather than import repository scripts at runtime. Concrete consumers are production extraction worker and existing live normalization/export subprocess calls. Follow Linux/POSIX capability failures explicitly; do not claim cross-platform cleanup without tests. Any refactor of script's runner is outside this slice.

Risk: v2 is intentionally a separate resource contract; do not quietly rename v1 request counts or ignore its limits. Full per-request browser/network governance is a separate extraction transport redesign. Actual browser execution can fail because browser binary/configuration is absent, independently from proxy denial. Both stay visible blocked/dependency outcomes.

Session incremental token counters are unavailable; no quota percentage inferred. Keep the amendment bounded and use one diagnosed repair per blocker.


SliceA audit: categories/api.extract_with_categories deliberately implements generic static/feed vs platform native category-mode requests; this explains why wrapper-only changes cannot expose full production fallback. categories CLI hardcodes browser-off policy; _cli_analysis and _cli_monitor similarly hardcode execution policies. Main CLI extract already supports explicit controls; share those controls rather than change defaults. Existing source-specific feed/tree/security tools are separate contract, not defects merely because they omit browser/model paths.

Installed Crawl4AI inspected without launching: BrowserConfig accepts proxy_config: ProxyConfig|dict, and ProxyConfig accepts server/username/password. Shared extractors/_browser.get_browser_config currently omits proxy_config; cannot assume Chromium honors Python HTTPS_PROXY. Add explicit configured-proxy preservation at this shared config boundary, test all tier configurations with synthetic proxy environment and redacted failures. Never print actual session proxy values.
