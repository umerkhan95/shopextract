## Dependency/lifecycle contracts
1. Explicit prepare: tiny pinned descriptor -> bounded download OR verified local sources -> offline builder -> complete relational validation -> identity/resource hashes -> staged atomic publisher. One-time<=768MiB/60s; no simultaneous importer. All316extensions,314category-used handles/2891overrides and allowed values_from lineage preserved. No inferred ancestor attribute union.
2. **Build-hook boundary refinement:** preparation is a separate explicit command. Hatch hook ONLY verifies/assembles preprepared data. This avoids importing eager shopextract.__init__ (which imports application/extraction dependencies) in isolated sdist/wheel builds. Load the SAME stdlib-only resource.py by explicit path; do not duplicate checks in hook or import taxonomy-build extras. This narrows optional G2 hook behavior without changing required explicit source-build preparation.
3. Ignored build/shopify-taxonomy complete resource -> force_include wheel destination shopextract/taxonomies/shopify/data/... AND sdist destination src/shopextract/taxonomies/shopify/data/... inside archive. Git remains code/tiny manifests/license/small fixtures only. Published sdist->wheel discovers embedded prepared data and runs only stdlib verification; no source fetch or YAML extra. Cold Git checkout uses explicit preparation/local override or clear missing-resource failure; normal pip/import never runs downloader.
4. Offline load validates pinned manifest/resource once -> normalized integrity -> immutable indexes cached by full fingerprint. Compact runtime<=512MiB; no95MB source parse per job. Source release/fingerprint/combined registry identity remain separate from unknown observed category version. Existing catalog instances do not mutate on publication.
5. Capture/adapter -> bounded relevant options -> existing mapper -> existing strict companion binder/codec; schema_for validates that bound object then reads metadata from matching catalog identity. All-category sweep uses this REAL path and reports14606source denominators; no full corpus in Product/job payloads.
6. Public rich Shopify capture -> explicit minimal category supplement (ID+handle checked) -> original support redirection -> shared path. Same producer dispatched by _extract and GuardedSources, same fixed constant consumed by guard. Parent strict validator rejects corrupted worker response before acceptance. Source visibility/access failure stays partial/unavailable, zero hidden query/model fallback.
7. Storefront-enabled runtime: ALL source-cache reads/writes off, including discovery/public acquisition; ordinary runtime caches unchanged. tokenA->deniedB forces B request, removal cannot read A cache, no secret hash/persistence. Existing committed checkpoint replay retains original source/time under matching saved policy; not a new acquisition/current-token assertion and never seeds cache.
