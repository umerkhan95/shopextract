# Feature specification — #24 Agent Tool API & MCP Server

Design author: feature_author. Date: 2026-10-16. State: proposed behavior, awaiting independent G1 review. Source: issue #24 read with `gh issue view 24 --json title,body`; no issue edits. This specification retains the entire epic scope.

## Outcomes and requirements

FR-01: Provide an opt-in structured Python tool API and a real MCP server exposing the same discovery, extraction, matching, changes and evidence operations. A reference MCP client must complete discovery → extraction → matching → evidence retrieval through an actual server process. Both surfaces expose equivalent validated JSON contracts; no mandatory paid provider, external account or hosted service.

FR-02: Publish explicit input/output JSON Schemas and `schema_version: "1.0"` in domain envelopes. Reject unsupported versions, unknown fields, wrong types (including boolean-as-integer), malformed IDs and non-finite numbers before work. MCP protocol negotiation and domain schema versioning are separate. Decimal facts serialize as decimal strings, UTC times as ISO-8601 strings; preserve missing/unknown/absent/observed distinctions, canonical identities, ownership and evidence references. No scalar default becomes an observed fact.

FR-03: Proposed v1 tool names are `discover`, `extract`, `match`, `changes`, `evidence`, `job_status`, `job_result`, `job_cancel`. The first four submit bounded jobs; evidence lookup is immediate. Discovery takes a URL and item cap, returning ordered source URLs and completeness/diagnostics. Extraction takes an allowed shop/product URL and item cap, returns normalized products/variants, support states, evidence references and an opaque catalog handle. Discovery returns normalized, source-mode eligible, policy-screened extraction inputs; rejected links appear only as diagnostics. Eligibility never grants new authority: extraction revalidates current origin/DNS at connection time (see G1 clarifications). Matching takes two authorized catalog handles, uses existing identity-aware matching and returns relation/reason/support rather than converting uncertainty into confirmed identity. Catalog handles may be minted from operator-configured saved captures as well as extraction. Changes takes two authorized capture handles and optional recheck handle, returning the existing reliable-change report (candidates, states, diagnostics, events and stable IDs); query calls do not trigger fresh capture or remote writes. Both changed and unchanged cases are valid results. Product/evidence/catalog/capture handles remain distinct typed references.

FR-04: Every operation returns a success/data or failure/error envelope with version, request ID and warnings. Errors contain stable `code`, safe message, `retryable` boolean and optional field details. Codes cover invalid_argument, unsupported_version, permission_denied, not_found, expired, resource_limit, timeout, cancelled, source_error, internal_error. Unknown and unauthorized cross-session handles return indistinguishable not_found; denied explicit source/tool access returns permission_denied. Backend access/parse/transport failures must not masquerade as a successful empty catalog; true supported emptiness and partial extraction are distinguishable by completeness and diagnostics. Credentials, server paths, stack traces and raw page text never enter error messages.

FR-05: Pagination applies to discovery URLs, extracted products, matches and change report collections. `job_result` takes job ID, collection, page_size (default 20; range 1–100), optional opaque cursor. A successful completed job's immutable result fixes ordering and membership; pages are deterministic with no duplicates/skips, even when other jobs run or underlying configured captures change. A page has items, next_cursor (null at end), collection, total and completeness. Cursors bind session, job, collection, version and effective page size. Tampering or mismatched context is invalid_argument, unknown ownership is not_found, eviction/expiry is expired. Empty collection has items [], total 0, next_cursor null. Result handles and evidence remain usable through terminal job retention, including after the last page; pagination itself never re-extracts or re-compares. Noncollection report metadata remains available alongside the selected collection.

FR-06: Job lifecycle is queued → running → succeeded/failed/cancelled/timed_out. A job never leaves a terminal state; repeated cancellation is idempotent and cannot erase already completed results. `job_status` returns state, timestamps and safe error/summary; `job_result` while unfinished returns state without fabricated data; failed/cancelled/timed_out jobs expose no successful partial catalog handles. `job_cancel` cancels queued/running work, stops network scheduling and propagates cancellation to in-flight work. Terminal publication and cancellation must have one deterministic winner. Timeout is total wall time from enqueue, not a per-request reset. MCP disconnection terminates owned running work and removes session handles. Restart invalidates ephemeral jobs/handles; document recovery by resubmission. MCP request cancellation and explicit job cancellation have documented distinct scopes; cancelling a submit request before acknowledgement cannot leak an orphan job.

FR-07: Default limits: 1 active job, 8 queued jobs, 32 retained terminal jobs, 600-second terminal retention, 30-second job deadline (client range 1–120 seconds), 1,000 result items per operation, 4 MiB retained job graph (result metadata, products, evidence and captured payloads together), 32 MiB aggregate retained graphs/session, 256 KiB input, 1 MiB single evidence response. Explicit source HTTP budget is 20 requests/job, 2 MiB response/request and 5 redirects/request, shared across discovery/extraction fallbacks. Operator may lower limits. Reaching requested item cap reports partial completeness unless source exhaustion is proven. Exceeding hard byte/request/time/queue limits yields explicit resource_limit/timeout, bounded cleanup, no fabricated complete result. No worker/thread can continue unbounded after timeout. Finite resource behavior must include retained results and pagination. No local model launch is needed.

FR-08: Permissions are immutable trusted startup configuration: exact permitted tools and normalized source origins (scheme/host/port), plus configured capture access. Default source access is deny, default writes are absent. Inputs cannot set DB/file paths, headers, credentials, proxy settings, arbitrary backend options or permissions. Read-only storefront network methods are GET/HEAD and narrowly defined read-only GraphQL queries required by supported extractors; no arbitrary GraphQL or mutations. All direct/fallback fetches, sitemap links, API endpoint discovery, redirects and subresources must go through the same guarded egress boundary. Disable any transport/browser/model fallback whose requests cannot be guarded; return an explicit diagnostic/error, and document supported server extraction modes. This does not alter existing standalone extraction defaults.

FR-09: Egress permits HTTP(S) public destinations only, additionally within startup allowlist; no URL userinfo, fragments used as credentials, non-web schemes or implicit proxy inheritance. Normalize IDNA, trailing dots and default ports consistently; deny ambiguous numeric hosts and encoded host bypasses. Resolve/check every destination and redirect; reject mixed public/nonpublic answers and loopback/private/link-local/multicast/reserved/unspecified IPv4/IPv6 (including mapped IPv4), metadata destinations and unresolvable names. Connect only to vetted addresses while retaining correct TLS hostname/SNI and revalidate each new connection; checking DNS then connecting through a separate uncontrolled resolution is insufficient. Revalidate redirects against both origin permissions and IP policy; no credentials forward across origins. Deny before request bytes reach an unauthorized destination. Policy can be tested with a controlled resolver/transport, but internal-target access is never enabled in shipped production defaults.

FR-10: Treat all source content as data, including descriptions, error pages, schema markup, sitemap URLs and published API configuration. Never execute page instructions, evaluate page scripts as tool commands, grant tools, follow instruction-supplied internal URLs, expose credentials or perform merchant/catalog writes. Output strings remain labelled untrusted; MCP descriptions and reference client guidance tell clients not to treat retrieved text as instructions. Source content cannot expand startup authority. No export, prune, save arbitrary file, merchant edit, purchase or remote write tool is registered. Internal bounded caches/job stores and existing reliable-report replay persistence are implementation bookkeeping, not user-authorized source write actions.

FR-11: Evidence lookup requires an authorized owner reference plus evidence ID. Verify the evidence belongs to that product/variant/capture/session graph, not merely that the ID exists globally. Return inspectable captured source support, source URL, capture time, pointer/retained payload or explicit unavailable/expired/not-retained state; never refetch silently or manufacture support. Configured saved captures are accessible only via operator-granted handles; DB path and arbitrary snapshot enumeration are absent from tools. Extraction-generated evidence is retained locally for job lifetime; identical IDs across owners cannot bypass ownership checks. Cap retained payloads without claiming truncated data is complete. Page content and secrets are not elevated into trusted metadata.

FR-12: Provide runnable self-hosted setup, MCP transport configuration, structured API examples, reference client complete flow, changes example, errors, cancellation/pagination examples and migration/operating limitations. The transport for this epic is stdio (one trusted local client per process); stdout is protocol only, stderr holds safe logs. A remotely hosted HTTP server/authentication platform is not required by #24 and is not promised. Real MCP interoperability must use a maintained protocol implementation/client rather than calling internal dispatcher functions in a demo. Dependency/version/Python compatibility is a production-research decision before G1. Existing Product/Variant constructors, extraction APIs, matching semantics, feed defaults and monitoring behavior remain compatible; opt-in security does not silently change legacy callers. All new core code/docs remain MIT and self-hostable.

## G1 clarifications — author revision, pending reviewer

G1-01 / FR-06–09: Resolve public DNS through a single owned disposable resolver subprocess running system getaddrinfo, never an executor/thread. One auxiliary process at a time: resolver and synchronous-domain worker cannot overlap. Each resolution gets min(2 seconds, remaining job deadline), then terminate/kill and reap within a 1-second cleanup grace. The same cleanup applies to job cancellation/disconnect. No socket connect or result publication after cancellation/deadline; ignore late resolver messages. If the child cannot be reaped within grace, fail closed: stop accepting jobs and shut down the server with safe stderr diagnostic; never accumulate abandoned workers or launch a replacement. State publication waits for owned cleanup. Time budget includes resolution, cleanup may extend terminal reporting by at most that stated grace. The complete ceiling is five when counting client/server multiprocessing resource trackers; one active auxiliary worker remains.

G1-02 / FR-07–09: Server fetches request `Accept-Encoding: identity`, accepts only absent or identity Content-Encoding, and rejects compressed/unknown encodings before decoding or reading the body, with source_error and reason unsupported_content_encoding. This is an explicit supported-mode limitation. No automatic decompression is invoked. Transport raw reads are bounded to <=64 KiB chunks; enforce the 2 MiB raw body cap incrementally before concatenation/persistence. Under identity policy raw and decoded body budgets coincide. Content-Length is only an early rejection hint, never authority: absent, false or smaller lengths cannot bypass streaming cap; incomplete/malformed framing is source_error. At cap exactly accept; above cap resource_limit. Discard offending response and mark operation failed or explicitly incomplete if existing supported partial results remain; never complete. Both terminal job graph and temporary received body are bounded independently.

G1-03 / FR-05,07,11: The 4 MiB job graph cap includes UTF-8 serialized products/result metadata plus all retained evidence/observations/capture bytes reachable through its handles, not only response pages. Count a shared capture once within a job by content/identity, including its metadata and references; conservatively charge its full size again in each different job even if physical objects are shared. Session aggregate cap is 32 MiB across running/terminal job graphs and configured-capture materializations; no unaccounted evidence cache. Admission/publication atomically reserves bytes or returns resource_limit without usable partial handles. Do not truncate captured data to fit while retaining a claim of complete support; optional unavailable retained payload must carry explicit not_retained state, preserve truthful observation metadata and already supported fact value. Default is reject oversized graph. Single evidence response cap remains 1 MiB; above it return resource_limit plus inspectable metadata, not a falsely complete payload. On cancellation/failure/timeout release unpublished data immediately; on expiry/eviction/disconnect release graph ownership and session charge atomically, with no dangling usable cursor/catalog/evidence handle. Configured captures must be materialized/charged within the same bound or rejected.

G1-04 / FR-03,08–09: Discovery normalizes and checks every candidate origin and current DNS before including it in output; shared request/deadline/DNS budgets apply. Cross-origin links without explicit startup permission are excluded, with safe rejected_source diagnostics and incomplete coverage where relevant, and are never fetched merely to inspect them. An allowed normalized URL can be listed yet subsequently denied by extraction if DNS changes to nonpublic; that is permission_denied, zero destination request bytes, no successful result. A returned URL guarantees schema/source-mode eligibility at discovery time, not future source availability or permanent address permission. No permission change is inferred from a sitemap, redirect or page instructions.

## Native Shopware read-only POST amendment — awaiting affected review

FR-08 clarification: In addition to fixed native GraphQL queries, the server must permit Shopware's native **read-only Store API product search**. Existing ShopwareExtractor sends POST to the normalized, allowed-origin `/store-api/product` route; this is required for the already promised native Shopware capability. It does not authorize merchant mutations or arbitrary HTTP POST.

The transport permits this search only when the trusted native Shopware adapter has constructed a per-job `NativeReadPolicy(shopware_search_url: normalized_exact_url)` after guarded resolution of public Shopware configuration. The exact URL must have an allowed origin, path `/store-api/product`, no query/userinfo/fragment, and undergo the same current-DNS/address/connection checks as every source. A page may supply a public API base/key as untrusted configuration data; it cannot itself register a route, change policy, or cause a custom path to become writable. Noncanonical configured paths receive explicit unsupported-source diagnostics in this server mode. No search-route policy is accepted in tool input, environment model options, MCP metadata or page instructions.

Search JSON must match the native immutable shape exactly: keys `page` (strict integer 1..20), `limit` (strict integer 1..20), `total-count-mode` exactly integer 1, `sort` exactly `[{"field":"id","order":"ASC"}]`, and `associations` exactly `{"children":{"limit":50},"seoUrls":{},"manufacturer":{},"cover":{"associations":{"media":{}}}}`. Reject unknown keys, strings/bools for integer fields, extra nested fields, arbitrary search/body/query/mutation content, alternate routes/methods and redirects for this POST before any target connection. The same request/time/body/graph caps and secret redaction apply. The native adapter's context GET remains a normal guarded GET; public source key/context headers never appear in errors or flow to another origin.

This amendment adds no tool or user write capability; it explicitly specifies a necessary existing read-only transport method. Other FRs and all prior limits remain unchanged. Independent affected review is required before enabling this POST policy in code.

### F02 configured capture bootstrap amendment — DESIGN ONLY, review pending (2026-10-16)

`async def ToolRuntime.bootstrap(*, timeout_seconds: float | None = None) -> dict` replaces synchronous bootstrap. Default total deadline is Limits.timeout_seconds, configured/client ceiling unchanged; time starts before admission/lock acquisition, including queue time. Constructor/config parsing never opens a capture database. All Python callers must await bootstrap; MCP read_resource awaits it. Successful schema_version/captures/limits and alias/capture/catalog/product owner capabilities are preserved; direct errors are safe ToolError codes, MCP resource errors retain safe code without paths or stored contents. No new tool is registered.

One bootstrap caller at a time owns a cancellable initialization lock; cached ready metadata returns a deep copy after closed/expiry checks, without rereading SQLite. Waiting callers have their own finite deadlines and cannot acquire an extra worker. A holder submits one private capture-materialization operation at a time through existing JobManager admission/slot and OwnedProcess, using remaining total deadline. No independent semaphore/worker pool/thread. Each worker builds one bounded graph; the existing graph reservation/session accounting applies to its temporary output and previously staged grants. Private job IDs/handles are not exposed until all configured grants succeed. On any failure/cancellation/close, discard only this attempt's private jobs/graphs/reservations, leave unrelated completed catalogs intact, clear initialization state, and reap the worker <=1s. No partial bootstrap cache or handles escape. A subsequent caller can explicitly retry; no automatic retries.

Inside the owned killable worker, BEFORE load_snapshot/schema migration/backfill/JSON decode/graph materialization, read SQLite numeric COUNT and length(CAST(... AS BLOB)) aggregates for the exact granted snapshot: legacy snapshots.products_json; normalized evidence_products record_json; owner graph_json/reasons; evidence_records metadata/status fields; each referenced evidence_payload encoded_payload charged for each reference, not imaginary dedup. Missing/corrupt schema/snapshot is explicit source_error; byte/item excess is resource_limit. Legacy bounded JSON may be decoded only after its byte preflight, then count validated before graph construction. Normalized rows are read incrementally with bounded batches, never unrestricted fetchall before budget check. No unbounded schema backfill path is allowed. Preflight uses a consistent read transaction so contents cannot grow between check/read; bounded SQLite busy behavior remains inside the killable worker. Every selected large text/blob must be checked by numeric length before fetching it.

Reuse existing snapshot/evidence decoding, product portable records and catalog_graph semantics. Adapt a narrow bounded-load seam rather than reimplementing trust/reliable algorithms. Worker incrementally assembles and serializes each full retained graph under graph_bytes, conservatively counting products, owners/evidence/captures and all retained copies; stop before adding an element that exceeds the cap. Keep byte-bounded worker IPC (existing maximum2*graph_bytes) and item_count; no aggregate multi-grant IPC payload. Parent receives a bounded graph and publishes through existing SessionStore, counts each staged graph against session_graph_bytes, and reveals grants atomically after the final success. Worker-created opaque handles must be checked collision-free on parent admission. Raw trusted db_path/grant data stays private metadata and never enters tool output/error. No assumption that trusted path means small database.

Implementation seams pending review: JobManager private materialization submission and exact-attempt discard; OwnedProcess domain capture payload; narrow monitor.evidence bounded reader/preflight preserving legacy loader default; domain graph serializer/reconstruction; bootstrap lock/task cleanup in runtime; async MCP resource and Python/examples/tests migration. Decide exact reader helper naming at G2, preserve this lifecycle and all existing capture owner capabilities. No production implementation of this amendment is authorized before affected G1/G2/G3 review.
