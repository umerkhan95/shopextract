## State and compatibility contracts

Expectations come from spec FRs and existing matching/reliable-change policies, not captured implementation output. Test exact typed support/owner relationships rather than global evidence-ID membership. Documented bookkeeping persistence may occur, but no tool accepts arbitrary writes/paths and no network write is possible except fixed read-only GraphQL POST operations. Extraction submitted by discovered URL must share the security path; discovery output is never authority to fetch an ungranted origin.

Job deadline includes queue wait. Terminal retention starts at terminal timestamp; status and pagination cannot extend it. Cursors are immutable views, not offsets into mutable job/global state. Catalog/evidence handle lifecycle is coupled to retained source jobs; changes uses explicitly operator-granted saved captures. Cross-session configured captures need fresh handles after restart. Legacy extraction callers retain existing defaults and constructor behavior.
