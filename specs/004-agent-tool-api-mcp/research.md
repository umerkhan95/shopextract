## Decisions and alternatives

1. Use official SDK **mcp>=1.30,<2** as an optional MCP extra, initially verify exactly 1.30.0. Package metadata probe reports latest overall 2.3.0, newest stable v1 1.30.0 with non-yanked Python >=3.10 distributions. Official main documentation now requires Python 3.11+, so an unbounded `mcp` dependency would violate project Python compatibility. The official v1.30.0 metadata declares Python >=3.10 and MIT; its README describes the supported maintenance branch and recommends a <2 bound. Use v1 low-level server/list_tools/call_tool and SDK ClientSession/stdio_client rather than hand-written JSON-RPC. Keep domain validation/schemas authoritative so generated wrappers do not silently widen coercion. Client and server must run real stdio and negotiate protocol independently of domain schema version. New SDK v2 APIs shown in main docs must not be copied into v1 integration. No need for CLI extras, HTTP hosting or OAuth. Exact SDK imports and teardown are verified in skeleton/red integration stage, not claimed tested here.

2. Guard at request AND connection boundary. HTTPX documents AsyncBaseTransport; HTTPCore documents custom public network backends for DNS requirements and separate TCP connection/TLS hostname. Installed httpcore exposes AsyncConnectionPool(network_backend=...), AsyncNetworkBackend and AnyIOBackend.connect_tcp(host,port,...). Decision: narrow HTTPX transport backed by an owned httpcore pool using a custom network backend. Validate normalized allowed origin on each request; manually process redirects with a shared budget; resolve each new TCP connection, reject any nonpublic answer, pass only the vetted numeric address into TCP backend, retain original origin for HTTP Host and TLS hostname. Reject environment proxies (`trust_env=False`), Unix sockets and unapproved methods. Use zero automatic retries, one connection/one active job, no global monkeypatch/private `_pool` replacement. A DNS-check wrapper around default hostname-resolving HTTPX is rejected because of rebinding. No custom TLS implementation. New connection/redirect/hostname behavior needs negative-control tests; this research establishes a supported seam, not a security proof.

3. Do not call legacy top-level extract() from tools. It can use environmental model credentials and browser fallbacks. Native guarded mode reuses existing Shopify/WooCommerce API parsers, Magento GraphQL/Shopware/BigCommerce extractors, structured HTML parsers and normalize()/capture provenance. Shopify/WooCommerce currently own AsyncClient; add optional injected-client seam with legacy default preserved, or reuse their pure mapping helpers with owned guarded fetch, whichever G2 shows is smaller. Existing Magento GraphQL/Shopware/BigCommerce already accept http_client through `_storefront`. All public runtime endpoint discovery and fixed read-only GraphQL calls remain guarded; do not expose arbitrary query/headers/credentials overrides. Structured HTML uses SchemaOrgExtractor/OpenGraphExtractor or UnifiedExtractor._extract_structured_from_html on guarded HTML, never UnifiedExtractor.extract()/extract_batch() browser paths. Feed pure parsing is reusable if supported by selected source mode; it must not call FeedExtractor._fetch_feed's owned client. Browser/LLM-only sources return explicit supported-mode diagnostics; the epic requires extraction tools, not enabling every legacy execution engine within a new security perimeter. Native storefront formats are not silently removed. `discover()` takes a client but catches broad errors and may use crawl4ai: use/refine a guarded discovery seam with no browser and explicit diagnostics rather than wrapping swallowed [] as successful emptiness. All raw dicts must carry real `_capture` before normalize; no fact inferred from defaults.

4. Reuse existing `match_products`/`classify_match`, `monitor.reliable.reliable_changes`, `monitor.evidence` and portable product serializers. Never duplicate their algorithms in tools. Evidence API's global ID lookup is insufficient authority: tool layer first checks session catalog/capture and exact product/variant graph, then scoped lookup. Configured captures are supplied by trusted startup mapping of external alias to DB path/snapshot IDs; API can return their opaque granted handles in trusted session/bootstrap metadata. Inputs cannot guess DB paths or enumerate ungranted snapshots. Extraction retains graph in owned job result; configured captures use real persistence. Reliable changes persists replay/report bookkeeping internally; disclose it, expose no prune/export/source writes. Same-supplier scope and snapshot ordering remain enforced by existing code.

5. Jobs are session-local bounded state, not a durable orchestration platform. One network job at a time; TTL and terminal count control retention. Request cancellation before submit acknowledgement removes/terminates the unacknowledged job; acknowledged background jobs use explicit job_cancel. Safe deadline enforcement for synchronous parsing/matching/SQLite calls cannot rely on cancelling an asyncio.to_thread task: threads continue running. Decision for G2: execute noncooperative synchronous domain work in **one owned disposable worker process**, kill/join on cancel/deadline and close resources before state publication. Async HTTP uses cancellation and cleanup in server process. Worker performs existing code paths, with no network capability passed; bounded serialization prevents large IPC. This adds a maximum third process during integration (reference client + server + one worker), no parallel jobs or models. No thread-based unbounded workaround. Publication uses one terminal-state transition; callbacks cannot publish results after cancellation. SQLite interruption/kill rollback and parent cleanup require explicit tests; replay identity must remain deterministic.

6. FR limits are proposed conservative v1 defaults, not measured capacity claims. Shared request/byte caps must be enforced while streaming including decompressed payload size; Content-Length alone is insufficient. Opaque cursors bind immutable job snapshots and use a session secret; no persistence/signing-key service is needed. Keep results/handles entirely session-owned, report expiry explicitly, release them on disconnect. Session/bootstrap capture descriptions are bounded and exclude paths/secrets. Include submitted-work bytes and serialization in deadline; bounded session count applies even with abandoned jobs. stdout is SDK framing only; safe logs go stderr.

## G1 response: tightened execution and allocation decisions

G1-01: Native OS resolver calls are potentially blocking. Use an owned short-lived subprocess for getaddrinfo; never asyncio/thread offload. Resolution budget <=2s or remaining deadline, cleanup/reap grace <=1s; discard late IPC. Serialize resolver and existing synchronous domain worker so three total integration processes suffice. Cleanup failure closes server admission and shuts it down; no retry/replacement workers accumulate. Resolver algorithm remains OS DNS; new lifecycle code only owns cancellation. R1/R2 exercise actual lifecycle/guard with a controlled resolver boundary, including late completion and repeated cancellation. No further external dependency/research required.

G1-02 supersedes the earlier decompressed streaming-counter suggestion: request identity encoding, reject any non-identity encoding on headers before body decoding; use bounded raw reads <=64KiB and cap accumulated raw bytes at 2MiB. Content-Length never substitutes for actual byte/framing checks. This avoids requiring a bespoke safe decompressor and prevents the existing _storefront aiter_bytes decoder from seeing compressed input. The outer guarded transport must reject encoded responses before it constructs a consumable decoded HTTPX response. Unsupported compression is a documented server-mode source_error; no legacy behavior changes. R3/R4 prove header rejection and real streaming/framing edges without mocking decoding/cap logic.

G1-03: Job 4MiB includes entire reachable serialized graph, shared capture counted once within job, conservatively once per owning job across jobs. Add 32MiB aggregate session charge for running/terminal/configured graph materializations; no separate unbounded evidence store. Reserve/release at publication/expiry/eviction/cancel with atomic owner invalidation. Reject oversized graph rather than automatic capture truncation; response-size failures retain inspectable metadata with explicit unavailable payload status. R5/R6 cover graph aliasing, aggregate admission and release.

G1-04: Discovery filters normalized candidates by startup origin and current public DNS; denied links become diagnostics and are not fetched. Return eligibility is conditional on later connection revalidation, so public→private DNS produces extraction permission_denied, never a stale authority grant. R7/R8 are distinct discovery/extraction interaction checks.
